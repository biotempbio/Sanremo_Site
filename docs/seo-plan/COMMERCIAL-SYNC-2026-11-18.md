# Sanremo: остатки ежедневно, цены еженедельно

Изменение по уточнению Сергея от 18.11.2026.

- Остатки обновляются раз в день после 06:30 МСК. Суточная задача GitHub перенесена на 06:30 МСК, после появления снимка BIO около 05:30 МСК; GitHub может задержать запуск.
- Цены — один раз за московскую календарную неделю. Обычный запуск — понедельник в том же утреннем окне; при пропущенном запуске обновление догоняется следующим успешным запуском.
- Обычные повторные сборки в течение дня не запрашивают каталог BIO снова. До 06:30 МСК автоматическое обновление не запускается, чтобы ранний импорт блога не забрал вчерашние коммерческие данные.
- Тексты, характеристики и фотографии зафиксированы в исходниках. Регулярная синхронизация их не меняет и не вызывает API карточек/изображений.
- Существующий документированный `/api/catalog/export?brand=Sanremo` остаётся пакетным источником. Из ответа применяются только `code`, `inStock` и проверенная РРЦ в рублях. Дилерская цена используется в памяти исключительно для проверки РРЦ и не публикуется. Отдельный облегчённый endpoint для выбранных полей не подтверждён; не заявляем, что BIO перестал включать остальные поля в своём JSON-ответе.

## Зафиксированные данные

Основа получена с уже опубликованного `https://sanremomachines.ru/` 18 ноября: **448 позиций**, 367 с положительным остатком, 57 машин, 2 кофемолки и 389 запчастей; **50 исходных фотографий**, около 2,07 МБ. Цены и остатки всех 448 позиций взяты из публичных данных действующей страницы, а не из старого Excel или демонстрационных значений. Статический снимок содержит дату источника **18.11.2026 05:30 МСК**, соответствующую `catalog-sync-state.json` production. Поля идентификации сверены с оригинальной выгрузкой 12 ноября; отображаемые описания и характеристики машин сохранены из текущих страниц. Состояние источника проверено до и после захвата — дата не изменилась.

`data/bio-catalog.snapshot.json` и исходные `/photo/catalog/*.webp` сохранены в Git. Производные изображения генерируются локально при сборке.

## Разделение кэша и контента

`public/catalog-commercial.json` — генерируемый публичный кэш только коммерческих значений и дат. При следующей сборке он восстанавливает последние успешно опубликованные цены и остатки, а тексты и фотографии остаются из Git. Это не возвращает цикл полного импорта контента.

Для остатков и цен хранятся отдельные `stockDataAsOf`, `stockSyncedAt`, `priceDataAsOf`, `priceSyncedAt`. Обновление остатков не освежает дату цены.

Если BIO отвечает ошибкой, возвращает неполный состав SKU, пропускает значение или отдаёт подозрительно нулевой склад, прежние данные сохраняются. Нулём отсутствие ответа не заменяется. Если при недельном обновлении цены невалидны, успешно полученные остатки могут обновиться независимо, а прежняя цена и её дата сохраняются. `catalog-sync-state.json` сообщает об ошибке синхронизации; ошибка API не заменяет витрину пустым каталогом.

Новые SKU и редакционные правки вводятся отдельно. Полный импорт контента вынесен в явную команду `npm run import:content`, для которой нужен `BIO_CATALOG_API_KEY`; она не входит в `prebuild`.

## Проверки и ручные команды

```sh
npm run sync:commercial
# Принудительный повтор конкретного потока (только при осознанной проверке):
BIO_SYNC_FORCE=stock npm run sync:commercial
BIO_SYNC_FORCE=prices npm run sync:commercial
```

Принудительный запуск не меняет тексты/медиа. Ключ остаётся только в окружении процесса; его значение нельзя выводить или коммитить.

Добавлены проверки частоты по МСК, сохранения цены при ежедневном обновлении, недельного обновления цены, защиты контента от перезаписи, отсутствия запросов к карточкам и изображениям, отказа при неполных/нулевых данных и ошибках API. Всего с существующими тестами — **31 тест**.

## Ответ о ключе

Прямая проверка с Mac значения, настроенного в Timeweb как `BIO_CATALOG_API_KEY`, получила от BIO `401 {"error":"Invalid or expired API key"}`. Timeweb API при этом возвращает 200. Это два разных доступа.

В то же время production Sanremo уже успешно опубликовал снимок 18.11.2026: источник 05:30 МСК, синхронизация 10:58 МСК. Поэтому сообщение «нужен новый ключ» было слишком сильным выводом из локальной ошибки. Точная причина расхождения ещё не установлена; не меняли и не перевыпускали работающие настройки приложения. Локальный 401 сам по себе не доказывает, что production больше не сможет обновляться. Новая схема сохраняет реальные опубликованные данные независимо от этого отказа.

## Граница выпуска

Изменения подготовлены в проверочной ветке вместе с SEO-пакетом. Main и production этим пакетом не изменялись; новый режим начнёт работать после принятого выпуска. Настройки управляемого Caddy (сжатие, кэш по путям, HSTS, нормализация URL) по-прежнему проверены локально и не должны называться применёнными в Timeweb. Подробности — `ops/web/README.md`.
