# Почтовый приёмник Sanremo на российском VPS

Отдельная служба для VPS `price-monitor` в Timeweb. Сайт и браузер обращаются только к BIO Lead Hub. Hub передаёт заявку по HTTPS на этот приёмник, который сначала записывает её в SQLite в `/var/lib/sanremo-mail-relay`, затем отправляет письмо через **российский SMTP**, доступный с VPS. Если SMTP временно не ответил, запись остаётся в очереди и повторяется с увеличивающейся паузой. В письме и записи есть время и версия согласия. Telegram не используется.

Служба **не** читает настройки `pricemon`, не меняет его код, базу и таймеры. У существующего мониторинга цен отправитель Gmail; его нельзя использовать для писем с персональными данными клиентов Sanremo. Реквизиты российского SMTP должны быть скопированы в `/etc/sanremo-mail-relay.env` защищённым способом после согласования доступа. Пароли, ключ и письма не выводить в журнал команд, CI и тикеты.

## Подготовка к включению

1. Проверить, что порт 443 на VPS свободен. Снять исходный снимок настроек сервера и состояния `pricemon`.
2. Разместить `server.py` в `/opt/sanremo-mail-relay`, создать отдельного системного пользователя и установить `sanremo-mail-relay.service`. Для SQLite использовать `RELAY_DB_PATH=/var/lib/sanremo-mail-relay/leads.db`.
3. Выпустить TLS-сертификат для отдельного домена или IP VPS, обеспечить автоматическое обновление. Hub обязан проверять сертификат по `SANREMO_RELAY_CA_B64`; небезопасные TLS-исключения запрещены.
4. Создать отдельный случайный `RELAY_SHARED_SECRET` для HMAC-SHA256. Хранить его только в защищённых переменных VPS и BIO Lead Hub. В Hub задать `SANREMO_RELAY_URL`, `SANREMO_RELAY_SECRET`, `SANREMO_RELAY_CA_B64`. Не использовать учётные данные SMTP как ключ HMAC.
5. На VPS задать `SMTP_HOST`, `SMTP_PORT=465`, `SMTP_USER`, `SMTP_PASSWORD` российского почтового сервера и `LEAD_RECIPIENT=sales@sanremomachines.ru`. Подтвердить, что почтовая инфраструктура и ящик обработки данных находятся в РФ.
6. Проверить health, отказ без подписи, идемпотентность `requestId`, запись в SQLite, техническую заявку `ТЕХ-ПРОВЕРКА` и письмо в ящике. Проверить, что `pricemon` и его таймеры работают как раньше. До реальной доставки не отмечать релизный чек-лист готовым.

`200` от приёмника означает, что заявка надёжно записана. Поле `delivery` равно `sent`, `pending` или `sending`; почтовая доставка подтверждается только статусом `sent` и фактом письма в ящике. При недоступности приёмника Hub отвечает ошибкой и форма предлагает телефон и почту.

Локальная проверка: `python3 -m unittest discover -s ops/mail-relay -p 'test_*.py' -v`.
