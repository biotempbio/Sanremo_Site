# Веб-сервер: пакет SEO от 18.11.2026

`static.caddy` — проверенный фрагмент для Caddy 2.10.2: gzip/zstd для текстовых типов, годичный immutable только у существующих `/_next/static/*`, суточный cache + must-revalidate у `/photo/*` и `/brand/*`, no-cache у HTML, HSTS на HTTPS на сутки, 308 для повторных слешей и адресов каталогов без конечного слеша, настоящий 404. Прямые URL исходных изображений сохранены.

`Caddyfile.preview` — HTTP-стенд; запускать из корня репозитория:

```sh
SANREMO_ROOT="$PWD/out" caddy run --config ops/web/Caddyfile.preview --adapter caddyfile
```

`Caddyfile.preview-tls` — изолированная проверка HTTP/2/HSTS и редиректов. Требует `SANREMO_CERT` и `SANREMO_KEY` с путями к тестовому сертификату и ключу. Сертификаты и закрытые ключи в репозиторий не включаются. Проверять curl с `--cacert`, без отключения проверки TLS. Не устанавливать тестовый сертификат в системное хранилище.

`Caddyfile.production.example` — пример целевой конфигурации; он **не подключён к управляемому frontend Timeweb автоматически**. Не менять тип приложения, тариф, TLS или DNS для его внедрения без отдельного плана. Перед подключением сохранить действующие API-прокси и редиректы; список legacy-адресов в примере соответствует прочитанным настройкам production на дату работы, перед выпуском его надо перечитать.

## Timeweb App Platform

Прочитано через API: production `243957`, frontend/next.js, `main`, `/out`, `spa_fallback=false`, compression выключено, глобальный заголовок `Cache-Control: no-cache`, 10 редиректов (включая www → apex). Production не изменялся.

Официальная [документация веб-сервера](https://timeweb.cloud/docs/apps/reverse-proxy) описывает gzip/zstd и глобальные заголовки; правил заголовков по пути там нет. В загруженной 18.11.2026 публичной [OpenAPI-схеме](https://timeweb.cloud/api-docs-data/bundle.json) модель `update-settings` для PATCH `/api/v1/apps/{app_id}` не описывает `reverse_proxy`. Поэтому пакет не содержит непроверенного PATCH для изменения production. Нужен подтверждённый API-контракт Timeweb для изменения reverse proxy и разделения кэша по путям. Произвольный `Caddyfile` в Git этого ограничения не снимает.

Доступ к Timeweb — только API. Токен из macOS Keychain `timeweb-cloud-api` получать в команде запроса, не сохранять в `.env`, файлы или постоянное окружение. При Timeweb 401/403 сообщить «токен Timeweb истёк или отозван». У API Timeweb в этой работе был 200; отдельный 401 вернул **API каталога BIO**.

Порядок выпуска: рабочий ключ BIO → успешная синхронизация цен/фото → сборка и приёмка стенда с реальными данными → проверка поддерживаемого способа настройки веб-сервера через API → ревью → публикация принятого кода → проверка канонического HTTPS apex. Пуш в `main` запускает production, поэтому эту ветку туда до приёмки не вливать.
